\begin{abstract}
%% Text of abstract
We introduce a library for brute-force solving of QUBO and Ising model
instances. The library provides a fast, distributed, GPU-based search of the
entire state space and guarantees finding the optimal solution for a give
problem. This comes at the price of computation time and scaling with problem
size. Nonetheless, we are still able to solve a 60 variable instance in
$2.5\cdot10^5$ seconds using only 8 H100 GPUs without any restrictions on the
density of the instance.
\end{abstract}

\section{Motivation and significance}

The fast-growing field of quantum technologies is steadily bringing us closer to
realizing practical quantum computers, which promise to provide computational advantage at certain tasks such as 
combinatorial optimization~\cite{Pirnay2023superpolynomial}, solving SDP problems~\cite{BrandaoSDP}, or quantum chemistry~\cite{QuantumChemistrySpeedup}. 
Presently, the available devices are referred to as the Noisy Intermediate-Scale Quantum (NISQ)
devices ~\cite{preskill2018quantum}. Although they do not offer capabilities of a fully-fledged quantum computer, these machines have attracted interest from both
scientific and business communities, what resulted in numerous
proposals for their applications. Implementation of these
applications requires development of appropriate software, what
introduces its own set of challenges. This work aims to
address a particular difficulty arising in the context of binary optimization problems, namely the expense of results verification of realistic NISQ devices. 
In most cases such a verification requires classical computation that scales 
exponentially with the problem size.   
%With the development of this field comes the challenge of preparing problems with
%known ground truth, used in further testing.
% This raises a question: How can one overcome the difficulty associated with the results verification?
One way to overcome this difficulty is to use instances with known, planted, solutions~\cite{PhysRevE.101.023316}. 
Yet, this limits the classes of instances one can study. Our approach allows finding optimal solutions for arbitrary
instances, regardless of their density. This significantly pushes the limits of the direct device verification.

\subsection{Software architecture}
Our distributed bruteforce solver is built on top of our \texttt{omnisolver} framework. The solver utilizes massive
parallelization on two levels:
\begin{itemize}
    \item Parallelization via usage of CUDA-enabled GPUs.
    \item Parallelization across multiple GPUs and/or multiple hosts.
\end{itemize}

There are numerous libraries available for utilizing CUDA in Python programs. 
However, we found that for our use case, the easiest approach was to write the performance-critical parts of our code in C++ and use Cython as the integration layer.

For the distributed workloads, the subproblems are constructed by fixing \texttt{num\_fixed\_vars}
variables to each of the possible values from $\{0, 1\}$. For $k$ fixed variables there are $2^k$
such subproblems, each with $N-k$ variables. The subproblems are distributed to workers, residing
either on the same host or on different network--connected hosts, via the Ray framework \cite{DBLP:journals/corr/abs-1712-05889}. 
Once the solutions of all the subproblems are gathered, the results are merged on the driving
host. In other words, the merging part of the algorithm is not parallelized. The distributed workflow is
exemplified in Fig. \ref{fig:arch}.

\begin{figure}
    \includegraphics[width=\textwidth]{figs/omnisolver-distributed-diagram.pdf}
    \caption{
        Visualization of an example execution of distributed bruteforce solver. The user supplies
        input QUBO, which is split into smaller subproblems by the controller. Then, the subproblems

\section{Impact}
The main contribution of this software lies in providing a distributed, scalable
brute-force solver for QUBO and Ising instances. With the current development of
NISQ devices, especially the D-Wave annealer it allows for extensive testing of
such architectures by providing instances with a known ground truth. In the
current landscape of computational architectures this is crucial as there are
many emerging potential applications of this particular computing approach. As
such, rigorous testing is a necessity.

As our approach introduces virtually no communication overhead during the
computation, the computation can be distributed along many nodes and GPUs. For
instance, large AI training clusters can contain up to $10^5$ GPUs. This means
that in under an hour it could find a solution for an instance with 67 variables
which means, provided the instance is fully connected, that it could solve an
instance larger than the largest fully connected instance that can be embedded on
the D-Wave Chimera architecture. Embedding is the required  preprocessing, in which an instance of 
QUBO or Ising problem is encoded into the graph that represents the topology of quantum
annealer qubits. In general, the problem of embedding a general graph $G$ into a graph $H$ is NP-hard (as hard as
the initial problem of finding ground state of the QUBO/Ising model). In the case of Chimera topology the maximal instance that can be solved on 2048 D-Wave 2000Q annealer has 
65 variables, solving an instance with 67 variables would require a 2312 qubit device in Chimera topology. For more recent D-Wave annealers a 67 variables instance can be, in principle, embedded into
Advantage and Advantage2 devices, provided that sufficient number of appropriately connected qubits is available: 622 qubits for D-Wave Advantage (Pegasus topology), and 468 qubits for D-Wave Advantage (Zephyr topology).
In these cases possibility of embedding is determined by the location of the idle qubits (not operating) qubits - it may happen that the qubits necessary for the embedding are the idle ones.       




\section{Conclusions}
Our library provides the quantum computing community with the possibility to
certify solutions to arbitrary QUBO and Ising problems. Furthermore, being
part of a large framework, the software allows for smooth integration
with other algorithms aimed the these types of problems.
